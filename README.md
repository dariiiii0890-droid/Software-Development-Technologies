# Lab 18 — Optimization

## Опис проєкту

Проєкт реалізує пошук мінімуму та максимуму функції однієї змінної за допомогою методу золотого перерізу.

Реалізація виконана мовою C++ із використанням стандарту C++20. Проєкт містить статичну бібліотеку, демонстраційну програму, модульні тести та окрему програму для демонстрації обробки різних типів винятків.

## Структура проєкту

- `include/` — заголовкові файли класів та винятків.
- `src/` — реалізація статичної бібліотеки.
- `demo/` — демонстраційна програма пошуку екстремумів.
- `tests/` — модульні тести Google Test.
- `exceptions_demo/` — демонстрація обробки винятків різних типів.

## Реалізовані можливості

- Пошук мінімуму та максимуму функції.
- Використання методу золотого перерізу.
- Перевірка коректності вхідних параметрів.
- Обробка некоректних значень функції (NaN та infinity).
- Власна ієрархія винятків.
- Використання стандартних винятків C++.
- RAII-клас `ScopeLogger` для журналювання входу та виходу з функцій.
- Забезпечення сильної гарантії безпеки винятків.
- Автоматизоване тестування за допомогою Google Test.

Метод золотого перерізу застосовується для пошуку екстремуму унімонотонної на заданому інтервалі функції.

## Збірка проєкту

Необхідні інструменти:
- C++20-сумісний компілятор.
- CMake 3.20 або новіший.
- vcpkg.
- Google Test.

Команди для конфігурації та збірки:

```powershell
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x64-windows

cmake --build build --config Release
```

## Запуск програм

Демонстрація оптимізації:

```powershell
.\build\Release\OptimizationDemo.exe
```

Демонстрація обробки винятків:

```powershell
.\build\Release\ExceptionDemo.exe
```

## Запуск тестів

```powershell
ctest --test-dir build -C Release --output-on-failure
```

Проєкт містить 18 автоматизованих тестів, які перевіряють пошук екстремумів, граничні випадки, обробку помилок та збереження стану об'єкта після невдалого обчислення.

## Негативне тестування

Для перевірки ефективності тестів було навмисно змінено умову порівняння в алгоритмі. У результаті чотири тести пошуку екстремумів завершилися невдало, що підтвердило здатність тестів виявляти помилки реалізації. Після відновлення правильного коду всі 18 тестів пройшли успішно.
